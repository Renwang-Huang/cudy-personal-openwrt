# 酒店网络准备 · 验证记录

2026-11-04 UTC，在单台 Cudy TR1200 v1 上部署并测试。
当前环境仍是已有无线中继，不是实际酒店。没有重刷固件或软件重启，没有修改电脑主用无线和以太网配置。

## 观察与改动

开始时观察到 DNS 健康检查失败、约 9.7 MiB 可用内存及 2.21 的一分钟负载。
无线信号约 -27 dBm，初始客户端到上游网关的 20 次 ping 无丢包，但延迟有波动。
发现既有三节点自动测速组合的间隔为 10 秒，直连 DNS 固定为单一公共解析器。
这些现象不能单独证明同一个故障原因，因此分别验证解析、链路和代理。

部署后，实际 sing-box 运行配置确认测速间隔为 `3m`、容差为 150 ms，
并保留 `interrupt_exist_connections=false`。直连 DNS 跟随 DHCP；
系统在线软件源继续关闭，原有软件包没有升级，新增五个固定本地包后共 199 个包。

后续快照观察到 15–17 MiB 可用内存，一分钟负载约 0.60，状态灯观察服务显示正常。
前后负载、内存快照并非控制变量性能对照，不将变化完全归因于单项设置。

## 真实流量测试

| 检查 | 结果 |

| 2.4 GHz 客户端 DHCP / UDP DNS / TCP DNS / HTTPS | 通过，使用 CN 直连出口 |

下载结果反映本次节点、上游及单次连接，不是设备吞吐上限，也不证明已加速所有线路。
未新增 SQM、完整规则数据库或额外代理核心。

## 认证入口与事件验证

使用电脑局域网上的临时 HTTP 服务模拟以下响应，调用设备实际安装的 Travelmate 解析函数：

- HTTP 204 判为网络可用。
- HTTP 302 到认证域名、HTML meta 跳转及 JavaScript 跳转，均识别为认证入口。
- 无响应端口判为不可用，没有伪造成功。
- 检测出的认证域名能加入两个 DNS 实例；测试后撤销未提交配置，确认真实配置逐字节未变。

浏览器实查了中文概览和无线站点页面，已有上游可见，扫描及编辑入口存在。
没有提交扫描结果、切换酒店或自动填写任何酒店表单。

上游同步脚本通过九项隔离事件测试，覆盖 DNS 改变、DNS 不变、无关 LAN、非当前上游、锁竞争、
有线移除存在无线备选、无备选路由、代理停用及原生 ifup 分工。
设备上的只读检查显示 `direct_dns=current`；正常 DNS 事件与 LAN 事件没有触发代理重启。
真实 DNS 续租变更和 WAN 插拔没有在本轮实机制造，自动处理效果仍需现场验证。

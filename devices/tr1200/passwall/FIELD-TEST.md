# PassWall · 单台 TR1200 实机记录

日期：2026-11-03。仅覆盖一台 Cudy TR1200 v1，OpenWrt 25.12.5，Linux 6.12.94。

## 部署结果

- PassWall 26.10.29-r1、中文包已安装，LuCI 菜单位于“服务 → PassWall”。
- 核心为 sing-box 1.13.21-cudy-lite.3，自编译 MIPS 小端软浮点版本。
- dnsmasq 2.93-r99 保留 DHCP、普通 DNS 和 nftset；不包含 DNSSEC 及其大体积依赖。
- 完成保留配置升级，原 SSH 密钥、管理员密码、网络、无线、Argon 和中文设置保留。
- PassWall 初始化为 DHCP 增加 `localuse=1`，为防火墙增加集成 include；既有防火墙规则已按 UCI 语义核对一致。
- 插件默认提高管理服务并发数，现场已恢复原有管理服务配置。
- 包装脚本使用单线程、24 MiB Go 内存软目标与积极回收；精简核心约 4.83 MiB。
- 初次部署时可写空间约 2 MiB，代理和 SOCKS 服务关闭；真实节点迁移后的状态见下文。

## 真实节点与无线中继

后续按设备所有者要求，使用已有路由器的 2.4G 直连网络作为上游。
TR1200 的上游地址处于 `10.0.24.0/24`，网关为 `10.0.24.1`，与已有路由器管理地址 `10.0.0.1` 属于同一台上游设备。
TR1200 的 LAN 管理地址仍为 `192.168.20.1`，没有开启运行时软件源或升级已安装组件。

上游旧版 PassWall 实际通过本机 SOCKS 连接独立 sing-box 的 VLESS Reality / TUIC 自动测速组合。
迁移时提取真实节点，转换成新版 PassWall 原生 Sing-Box 节点，没有复制上游的回环 SOCKS 地址。
两条 VLESS 节点、一条 TUIC 节点及自动测速组的生成配置均通过精简核心检查。
TUIC 保留原证书信任与主机名校验，没有启用跳过证书验证。

| 实测项目 | 结果 |
| --- | --- |
| 无代理基线 | TR1200 经上游直连网络进行 HTTPS 请求，观察到国内出口 |
| 单节点传输 | 实机分别使用 VLESS Reality、TUIC 访问公网 HTTPS，观察到美国出口，核心 RSS 约 26 MiB |
| 原生透明代理 | URLTest 组合、DNS 和 nftables TCP/UDP 转发实际运行 |
| 有线 LAN 客户端 | UDP/TCP DNS、国内 HTTPS、代理 HTTPS、UDP/STUN 和 1 MiB 文件下载通过 |
| 5G 无线客户端 | 实际关联并获取 LAN 地址，完成同类网络与文件传输测试 |
| UDP 路径 | STUN 获得响应；上游抓包未发现明文 STUN，观察到代理服务端口的加密 UDP |
| 国内分流 | 国内 IP 分流及用户自定义直连/代理规则保留；DNS 使用 71 条精简域名后缀，覆盖范围与完整表不同 |
| 状态兼容 | 修正精简核心路径导致的 TCP/UDP 状态误报，保留核心原启动参数 |
| 开机恢复 | 软件重启后管理与上游恢复，等待原有 60 秒代理延迟及初始化后，有线客户端传输复测通过 |
| 闲置接口测试 | 最终仅连接 `wlo1-quad`，主用 Wi-Fi、有线连接、主路由、策略规则及系统 DNS 均与测试前一致 |

早期使用主用接口切换网络时出现超时，曾暂时怀疑 2.4G 同频中继。
后来用闲置接口、独立路由表、仅该测试地址的临时邻居固定进行复核，2.4G 和 5G 均通过完整选定测试。
早期未排除主用连接切换、同网段多接口和 ARP 干扰，不能将其确认为路由器同频故障，相关判断已撤回。
当前为 **2.4G 上游 + 2.4G AP + 5G AP + 有线 LAN**，两路下游 Wi-Fi 均开启。
设备所有者目前没有额外网线，因此本次没有改用有线 WAN。

首次启用完整配置和后续检查期间出现异常中断；重启前日志不足，无法证明单一原因。
用户随后正常断电上电并确认使用 5V/2A 供电。改用精简 DNS 表后继续验证，
保留原完整域名表于只读系统与私有备份。运行适配代码见 [runtime/](runtime/README.md)。

## 首次启动观察

首次升级期间写入和启动时间长于初始预估，电脑观察到多次链路重建。
随后设备恢复到原管理地址，SSH 和核心服务通过核对，未发现内核崩溃或内存耗尽记录。
不能仅凭短时链路中断认定启动循环；此次没有进行 Reset 或恢复出厂设置。

构建过程发现本机默认文件掩码会产生带组写位的目录，现场已规范根目录、`/etc`、
`/etc/uci-defaults`、`/tmp` 权限。后续构建必须使用 `umask 022` 并检查镜像目录权限。

## 备份、回退与未覆盖范围

安装前后配置、初始完整闪存和原 v0.1.1 镜像均保存在本机私有目录。
原 Argon 回退配置和脚本也已保留。私人配置、密码、SSH 私钥、截图和测试凭据未上传。

只关闭 PassWall 时，可在管理页关闭总开关，或通过 SSH 执行：

```sh
/etc/init.d/passwall stop
/etc/init.d/passwall disable
```

恢复到原 v0.1.1 需要使用匹配型号的旧镜像和安装前配置进行升级回退，
不建议通过逐个卸载 DNS、Lua 或网络依赖包恢复基础系统。

尚未验证真实订阅、峰值代理吞吐、长时运行或多连接负载；1 MiB 下载只是传输验证。
有线 WAN、完整无线性能仍需后续检查。当前仍作为单台设备的候选配置使用。
最终状态见 [upstream-validation.json](upstream-validation.json)，不能据此推断长期稳定性或最大负载能力。

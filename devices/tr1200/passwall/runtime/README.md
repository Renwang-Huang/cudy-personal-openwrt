# TR1200 实际节点运行适配

此目录保存实际节点迁移测试中采用的通用源码变更，不包含节点、订阅、无线密码或设备备份。
现场测试及其边界见 [实机记录](../FIELD-TEST.md)。

## 精简 DNS 分流

`files/usr/share/passwall/rules/chnlist` 用 71 条域名后缀覆盖 `.cn` 和常见国内服务，
替代完整的国内域名表。保留国内 IP 分流以及设备所有者自己的直连、代理和阻断规则。
未列出的域名采用远程 DNS；其连接是否直连仍由目的 IP 和用户规则决定。
这份清单不能覆盖完整国内域名表中的每个域名。

TR1200 仅有 128 MiB RAM。现场首次启用完整配置时出现重启，重启前记录没有保留下来，
当时供电规格也未知，因此无法确认单一原因。之后改用精简域名表，并更换已确认的 5V/2A 供电继续验证。

## 核心运行状态显示

`patches/001-cudy-lite-status.patch` 修改 PassWall 26.10.29-1 的 LuCI 控制器，
让 TCP/UDP 状态检测同时识别实际核心路径 `/usr/libexec/sing-box-cudy-lite`。
核心包装脚本会转交给该路径；上游原有检测只匹配临时 `bin/` 路径，会错误显示“未运行”。
补丁只修改进程检测条件，不改变协议实现、流量规则或核心启动参数。

在解压后的固定 PassWall 源码根目录应用补丁：

```sh
patch --batch --fuzz=0 -p1 < /path/to/cudy-personal-openwrt/devices/tr1200/passwall/runtime/patches/001-cudy-lite-status.patch
```

随后按原 OpenWrt 包构建流程生成组件。组装后续镜像时，按 `config.json` 的顺序应用
本目录 `files/` 与固定版本关闭源目录；`passwall_source_patches` 声明控制器补丁的位置。
这些声明仍需镜像组装流程实际执行，不代表完整自动镜像构建器。

## 无线中继与测试隔离

当前采用 2.4G STA 接上游，同时提供 2.4G、5G AP 和有线 LAN。
两路无线均已由本机闲置接口 `wlo1-quad` 实际连接，完成 DHCP、UDP/TCP DNS、国内和代理 HTTPS、
UDP/STUN、1 MiB 下载测试；测试结果见 [upstream-validation.json](../upstream-validation.json)。

早期在同一电脑切换主用无线、并保留同网段有线连接的测试中出现超时，曾暂时归因为同频中继。
后续改用独立闲置接口、专用路由表和来源策略，并临时固定仅该测试客户端的邻居项，
在不改动主用连接、主路由表和 DNS 的条件下，两路无线都通过。
因此撤回“已确认同频 AP/STA 故障”的判断；早期测试不能排除电脑路由及 ARP 干扰。

`wlo1-quad` 与主用接口共用无线芯片，驱动声明支持两客户端、两信道并发。
最终核对主用 Wi-Fi、以太网、主路由表、策略规则及系统 DNS 均与隔离测试前一致，
临时测试连接、策略和密码文件已清理。本次没有验证有线 WAN。

实际节点配置应通过管理界面或私有导入完成。不同 PassWall 版本的全局节点字段和节点类型有差异，
迁移时应重新生成配置并运行核心检查，不能直接覆盖另一台设备的完整 UCI 配置。

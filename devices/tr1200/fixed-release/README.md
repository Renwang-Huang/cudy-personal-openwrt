# TR1200 固定版本维护规则

当前设备采用固定版本，不配置在线软件源，不自动升级。
后续需要升级或个性化时，由设备所有者明确提出，再从 GitHub 中保存的源码、配方和固定输入进行维护。

## 设备状态

- `/etc/apk/repositories` 和 `repositories.d/*.list` 只保留固定版本说明，没有有效软件源条目。
- 当前已安装包、运行功能、配置和包管理器保持原样；可继续离线安装经审核的本地 APK。
- 当前没有软件自动升级任务；组件的手动更新按钮不作为后续维护路径。
- 原软件源配置已备份到设备和电脑，备份不作为有效源加载，也不提交私人设备配置。
- 精确软件包版本见 [installed-packages.json](installed-packages.json)。

禁用软件源不会冻结无线、网络、节点、灯语等普通运行配置；这些仍可按需要调整。
PassWall 的节点订阅和分流规则属于运行数据，与软件包源不同，本次不改动这些配置。

## GitHub 中的维护输入

| 范围 | 保存位置 |
| --- | --- |
| 基础 OpenWrt 与 feeds 源码快照、设备补丁 | `reference/sources/`、`reference/tr1200/` |
| 精简代理核心、PassWall、DNS 源码与裁剪配方 | `reference/passwall/`、`devices/tr1200/passwall/` |
| 现代管理界面源码及适配 | `reference/ui/`、`devices/tr1200/ui/modern/` |
| 原 Argon 主题和固定安装输入 | `devices/tr1200/ui/argon/`、`reference/ui/` |
| 灯语配置 | `devices/tr1200/leds/` |
| 当前现场软件版本与关闭源记录 | 本目录 |

基础软件包配方和 Go 模块依赖文件保留固定来源；GitHub 中的归档不是所有传递依赖
原始源码和完整工具链的自包含镜像。构建机可在明确升级/构建任务中获取所需固定依赖，
设备运行时不需要加载这些软件源。

## 后续升级流程

1. 按用户提出的目标选定源码版本，修改并保留构建参数。
2. 检查内核匹配、闪存余量、依赖和必要功能，完成相应验证。
3. 保存设备配置和回退材料，再应用已验证的本地安装包或镜像。
4. 更新现场版本清单、源码记录及验证结果，同步到 GitHub。

新镜像组装时，将本目录 `files/` 作为最后一层文件叠加；PassWall 配方已经声明这层配置。
其中 `98-fixed-software` 用于在新系统首次启动时关闭可能由基础包重新带入的源配置。
它不是常驻服务，不阻止构建主机获取固定输入。

旧候选镜像及其固定输入保留历史状态；本次没有重新发布或刷写固件。
关闭软件源的当前实机验证见 [validation.json](validation.json)。

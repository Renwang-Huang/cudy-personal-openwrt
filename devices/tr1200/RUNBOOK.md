# TR1200 1.0 到货与恢复操作单

适用：标签确认为 **Cudy TR1200 1.0 / R46** 的 AC1200 旅行路由器。
AC1200 是速率等级，不能代替型号和硬件版本。以下流程没有授权或自动执行刷写。

## 1. 先验收原厂状态

- 核对机身完整型号、硬件版本和管理页的原厂固件版本，先测试网口和两个无线频段。
- 导出原厂配置，在电脑本地保存；它不等同于完整闪存或无线校准备份。
- 使用稳定的合规电源和网线。先保持原厂系统，不因候选镜像已经发布就直接上传。
- 首次进入自定义系统时只连接隔离电脑的 LAN；WAN 暂不接上游，避免启动期间交换机串流。
- 管理地址将变为 `10.0.0.1/24`。避免与现有同地址路由器接入同一网络；首次无线默认未配置。

## 2. 准备原厂恢复材料

在电脑的仓库根目录运行：

```sh
python3 devices/tr1200/scripts/prepare-recovery.py
```

它核验仓库备份的 TR1200 原厂 ZIP、厂商 MD5，并在 `work/tr1200-recovery-kit/` 生成
原样的 `recovery.bin` 和校验清单。它不连接路由器、不启动 TFTP、不修改防火墙。
已备份原厂包为 2.5.41；到货型号、硬件/地区与版本限制必须先核对，再决定是否使用。

[Cudy 官方中文恢复教程](https://www.cudy.com/zh-cn/blogs/faq/how-to-recovery-the-cudy-router-from-openwrt-firmware-to-cudy-official-firmware)
规定：TR1200 恢复接 **WAN** 口；电脑 IP 为 **192.168.1.88**；请求文件名为
**recovery.bin**。按住 Reset 上电，开始传输或快闪后松开，等待恢复完成。
正常管理使用 LAN，恢复使用 WAN，不要混淆。

探测恢复请求时，TFTP 服务使用独立的**空目录**，只记录请求，不提供恢复文件，
避免一次探测变成实际刷写。收到请求只证明引导程序能发起 TFTP，不证明验签、写入
或完整恢复已通过。真正恢复时才将正确的原厂文件放入服务目录，并放行必要通信。

## 3. 核对中间固件与实际分区

原厂 GUI 需要对应型号的 Cudy 签名中间固件；候选 sysupgrade 不是原厂签名固件。
不能从原厂 R46 身份直接 sysupgrade。中间固件包在 `reference/tr1200/`；其来源和
校验值见该目录的锁文件。已解包确认归档中间固件为 23.05.3 / `cudy,tr1200`。它在内核前还包含前缀数据；
原厂升级过程是否及如何更新这些区域未经验证，不能假定中间固件步骤绝不会涉及引导区域。
是否适用新机当前版本，须根据实际信息判断。

获得目标 TR1200 的 OpenWrt 只读访问后，可从电脑通过 SSH 标准输入执行采集脚本：

```sh
# TR1200_ADDRESS 必须替换为已经通过物理连接确认的新机地址。
ssh root@TR1200_ADDRESS 'sh -s' < devices/tr1200/scripts/collect-readonly.sh > work/tr1200-device-inventory.json
python3 devices/tr1200/scripts/check-device.py work/tr1200-device-inventory.json
```

不要把当前网络中的旧 `10.0.0.1` 设备当作新机。脚本仅输出型号、版本和 MTD 元数据，
不刷写、不改网络、不重启、不读取密码或校准内容。JSON 保存在忽略的 `work/`，不公开上传。

清单检查通过仅表示所提供的信息与预期结构一致，不是对物理设备身份的认证，也不是刷写许可。
旧 DTS 的 backup 偏移可能错误；按名称备份 backup 不能证明已读取闪存末尾的真实区域。

## 4. 备份并检查候选镜像

- 核对实际偏移后，保存 U-Boot、环境、factory、bdinfo 等关键数据，能可靠读取整片
  闪存时另存完整备份。先确认读的是正确范围，不给未知 MTD 编号套用通用命令。
- 备份复制到电脑后检查大小和文件完整性，保留设备独有的校准与 MAC 数据。
- 从本设备 Release 下载 v0.1.1，并完成文件完整性检查。镜像约 6.31 MiB。
- 仅在目标已进入对应 OpenWrt 中间/运行系统并核对分区后，在目标执行非刷写检查：

```sh
sysupgrade -T /tmp/verified-tr1200-sysupgrade.bin
```

路径需替换为已经上传并完成完整性检查的实际文件。检查失败时先分析原因；不加 `-F`。
首次从旧中间固件迁移到 25.12 时，采用不保留旧配置的迁移方案，避免旧插件和配置串入。
这里不提供自动执行的实际刷写命令。

## 5. 首次启动验收

- 等待完整启动，用 LAN 访问 `10.0.0.1`；必要时电脑有线网卡设为同网段的未占用地址。
- 核查启动日志、MTD 布局、VLAN、LAN DHCP、管理页面和密码设置，再逐项验证上游、无线与 USB。
- 将首次启动、冷启动与重启分开验收。未确认 WAN/LAN 隔离前不接生产网络。
- 启动失败但 bootloader 恢复仍可用时，按官方 WAN/TFTP 流程恢复原厂。
  Reset 只清配置，不会把 OpenWrt 自动变回原厂。U-Boot、Flash 或校准数据损坏可能需要维修。

[Cudy OpenWrt 声明](https://www.cudy.com/en-us/blogs/faq/openwrt-software-download)
明确不为非 Cudy 软件及安装了该类软件的产品承担保修；刷回原厂不代表官方承诺恢复保修。

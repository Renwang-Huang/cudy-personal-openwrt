# TR1200 V1.0 单台实机记录

日期：2026-11-02。范围为一台原厂 TR1200 V1.0，不外推至其他批次或硬件版本。

| 项目 | 实测 |
| --- | --- |
| 原厂系统 | 2.4.15 CN，构建 20250721-164017 |
| 内存 / 闪存 | 128 MiB / EN25QX128A 16 MiB SPI NOR |
| 中间系统 | Cudy 签名中间固件，OpenWrt 23.05.3，`cudy,tr1200` |
| 定制系统 | v0.1.1，OpenWrt 25.12.5，Linux 6.12.94，`cudy,tr1200-v1` |
| 现场 LAN | `192.168.20.1/24`，用于避开既有网络；发布镜像仍默认 `10.0.0.1/24` |

## 已完成

- 原厂正常管理、配置导出、匹配中间固件上传及其返回信息核对。
- 通过 Cudy 中间系统取得只读设备信息；实际分区检查通过，发现旧 backup 偏移错误。
- 在中间系统保存并核验引导、环境、校准、固件、debug 和设备信息等可确认分区。
- 上传 v0.1.1 后校验文件内容，在设备执行 `sysupgrade -T` 成功，迁移时不保留旧配置。
- 定制系统启动成功；backup 实际偏移已为 `0xfe0000`，与 firmware 不再重叠。
- 引导、factory 和 bdinfo 与写入 v0.1.1 前的备份保持一致；补存真实尾部分区，保存升级后的完整闪存备份。
- IPv4 LAN 管理、管理员密码设置、中文 LuCI 实际登录、HTTPS 及页面脚本加载通过。
- 软件重启后型号、版本、管理地址、密码、主机名和语言保留；网络、dnsmasq、SSH、
  uhttpd、rpcd 正常运行，防火墙规则已加载，未发现严重内核错误。
- 电脑恢复原有 DHCP 配置后取得新网段租约，能够直接访问管理页；原有 Wi-Fi 上网保持正常。
- 识别两个无线 PHY；未创建可连接的无线 SSID。

备份和会话仅存本机私有目录，没有公开设备标识、凭据、配置或闪存内容。
升级后的完整闪存备份包含设备私有数据，不作为普通升级镜像发布。

## 恢复入口与迁移时的观察

按住 Reset 上电、连接 WAN 后，可访问 `192.168.1.1` 的 **Firmware Recovery** 网页。
该环境提供 DHCP，电脑取得 `192.168.1.88`。指示灯未闪烁，监听期间未捕获 TFTP 请求。
没有向恢复页上传文件；正常退出后原厂系统与管理员密码仍可用。
网页入口可访问不等同于已验证镜像验签、写入或完整恢复。

中间系统的 IPv4 管理一度不可达，通过独立网线上的 IPv6 SSH 完成身份、分区和迁移检查；
定制系统启动后 IPv4 管理正常。采集脚本已修正与 OpenWrt jshn 的 nounset 兼容问题，
并在中间系统和定制系统实际执行通过。
